## Open findings and verification limits

This section records the initial review. The secondary-action finding is resolved
by the follow-up below; the clause-coverage and physical qualification limits remain.

1. **Implementation mismatch: secondary action size.** `MainActivity.footer()`
   sets the clickable notification settings/retry/help view to a 48 dp minimum,
   below `LLR-AND-UI-002`'s 60 dp action-height requirement. The adjacent Updates
   view uses 60 dp. Keep the requirement and fix the implementation in
   [issue #16](https://github.com/toastfr35/ZmalaApp/issues/16), including native
   measurements and an audit of photo-sharing/dialog actions. This is a source
   finding; device measurements were not run in this review.
2. **Test coverage is not clause coverage.** The baseline checker maps all 16
   Android requirements to plans, but one mapped test does not prove every clause.
   `PushAlertsTest` covers explicit token upload/removal and signed alerts;
   `CallbackAlertsTest` covers callback reconciliation. Neither currently asserts
   the complete app/channel enablement matrix through `PushAlerts.register`.
   The expanded verification text records that remaining check. Similarly,
   update policy/HTTP tests do not establish periodic-job execution or the actual
   six-hour/manual-refresh behavior of `AppUpdates`.
3. **Hardware qualification remains separate.** Physical optical QR decoding,
   real FCM/Doze/locked-screen delivery, audible speech and moving-camera quality,
   cross-network TLS/TURN interoperability, system photo-picker behavior and
   signed self-updates on the planned Android versions were not run. The Python
   hardware plans and opt-in `RemoteMediaTest` are not evidence of a pass merely
   because they exist. App/App photo sharing also needs paired-device qualification;
   the local call/photo fixtures do not establish that result.

[Issue #16](https://github.com/toastfr35/ZmalaApp/issues/16) is addressed in
version `0.4.5` / `118`. A common action-sizing helper applies the minimum and
wrapping to notification footer actions, photo Share/Cancel/Stop, app-created
dialog buttons and the automatic-update toggle. Existing actions retain their
callbacks. Before the runtime fix, all four new native action-size tests failed:
the footer and photo action measured 126 px, and setup/update dialog buttons
142 px, against a 158 px minimum on the disposable emulator.

After the fix, the four action-size tests passed at both 100% and 200% font scale
in English and French on an API 37 emulator. They assert rendered clickable bounds,
complete labels, photo/control separation in portrait and landscape, and action
callbacks. French 200% footer/setup/update screenshots were also inspected.
The JVM suite passed 36 tests, including history capacity/saturation/reload;
debug APK and instrumentation APK builds and Android lint passed. The final combined
native run passed all 17 tests across action sizing, UI language/improvements,
contact interfaces and enrollment flows; all three repository tooling tests passed.

Broader native verification exposed stale HTTP fixture contacts without the
mandatory `sip_uri` and a test reading enrollment storage before Android dispatched
the Forget setup dialog listener. Fixtures now satisfy the existing contract and
the test waits for the observable deletion. The scanner cancellation test now sends
Android Back and inspects the resumed setup activity, allowing Android to recreate
it while the scanner is open. App validation and wire behavior are unchanged.
These emulator checks do not close the physical qualification gaps above.

The follow-up requirements check maps 55 runtime source files, nine anchored LLRs
and 43 test plans to the unchanged seven HLRs and nine LLRs, with no unmapped
Android requirements. GitHub Verify must pass on the final pull-request commit.
